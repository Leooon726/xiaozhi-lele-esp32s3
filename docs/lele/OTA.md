# 自有固件的 Wi-Fi OTA 后续计划

当前保留小智手动 OTA 入口，音乐变体禁用自动安装官方固件，避免覆盖乐乐/音乐改动。**没有部署或验证自建 OTA 服务**，GitHub push 本身不会更新设备。

现有 16 MiB 分区保持官方布局，应用槽上限 0x3f0000，独立 assets 从 0x800000 开始。设备板型/变体名是兼容性的一部分；debug/music/stock 不能无条件混用更新元数据。

下一步先确认当前 OTA 实现如何区分 app 与 assets，发布同硬件/同分区的应用；唤醒模型或资源格式改变时必须设计资源一致更新，不能假设只 OTA xiaozhi.bin 就完成全部升级。

建议流程：

1. 固定已实测提交、变体、SDK 和依赖锁；本地可重建，并记录 app SHA-256/大小。
2. 规划受控的 HTTPS 发布地址和版本元数据，明确板型、大小、摘要和兼容资源版本；不把凭据放固件仓库。
3. 检查应用槽空间、下载校验、失败处理/回滚，以及更新时语音和音乐的停止顺序。
4. 在有完整本地备份且可 USB 救援的设备上，由用户明确授权测试一次手动 OTA，再做断网/失败恢复。
5. 通过后再设计自动检查和发布流水线；独立决定是否在正式版本关闭本地 debug 入口。

不要重新启用官方自动升级来冒充“自己的 OTA”。未经授权不要发布 Release、推送固件、修改设备 OTA 地址或更新实际设备。
