## 行为

- 仅本板两个音乐变体的默认 LVGL 助手 UI 启用。
- 正常 idle 持续 60 秒、没有触摸/按键/唤醒活动后，关闭 ST7789 显示输出，
  背光临时渐变到零。ESP 不进入 light/deep sleep，不停止应用、音频唤醒、
  Wi-Fi 或触摸，也不改变本板 Wi-Fi 性能策略。
- 菜单（含 Songs/Display）、准备传输、Wi-Fi 传输及独立 USB 模式保持亮屏。
  所有非 idle 状态均保持亮屏，包括连接、聆听、播报、通知、升级、配网及
  当前音乐播放所使用的 notifying 状态；此版没有另做音乐播放时息屏策略。
- 屏幕关闭时，第一次触摸的整个按下/移动/松开过程只请求亮屏，不启动对话，
  也不触发播放/停止。随后独立的正常点击恢复原助手交互。
- 息屏时物理键单击只请求亮屏，长按仍可打开菜单；开启 press-to-talk 时，
  原来的按住说话流程仍由现有按下/松开回调处理，进入聆听会亮屏。
- 识别到本地唤醒词时先请求亮屏，再检查协议/联系云端；即使协议未就绪也
  会亮屏。连接、聆听、说话等状态变化也会亮屏。
- 恢复保存的 display/brightness，保留 1–100 的正值，非正值按现有亮度恢复
  规则取 10，异常大值夹到 100。零亮度和息屏状态均不写 NVS；重启正常亮屏。
  使用原背光渐变，开始亮屏响应后需几百毫秒到达目标亮度，不是瞬间跳亮。
- 普通状态栏时钟、松鼠图重绘不作为用户活动延长计时。

## 实现约束

- screen_idle.h：主任务的 60 秒计时，活动/非 idle 保持时更新计时基准。
- LeleLcdDisplay：实际面板显示开关与背光，未销毁 LVGL，不复位面板/触摸，
  不切断共享电源。关屏前在 LVGL 锁内复查输入活动时间，避免与刚到的触摸竞争。
- LeleMenu：沿用 100ms 主任务轮询；LVGL 回调仅排队并吞掉首次唤醒手势，
  不在回调中操作面板、音频或 NVS。菜单/传输和应用状态共同决定能否息屏。
- Application：通过现有 Display 接口在本地唤醒及非 idle 状态变化时亮屏；
  调用限定上述板级配置，不引用具体板类，不改变音频或协议逻辑。
- 面板打开/获取 LVGL 锁失败时保留唤醒请求，下一轮重试；面板关闭失败保留
  亮屏状态并重新计时，不能把失败当作已关屏。亮屏成功后请求完整重绘。
- Backlight::SetBrightness 比较目标亮度而非渐变过程的当前样本，修复“刚开始
  降到零就请求原亮度”时请求被忽略的问题；永久设置仍保存，临时息屏不保存。
  这是本轮唯一公共背光行为修复，不引入新电源管理策略。
