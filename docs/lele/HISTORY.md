# 开发历史（关键决策）

上游小智 v2.6.0，提交 `4de00aed740595a8713b01f8332b9b2cf30685bc`；改动保留上游 Git 历史。音乐参考为 `jianglixi-oss/xiaozhi-nas-tf-music` 提交 `3ede3d71362ade67387792334a6c17ace298220d`（MIT）。

| 阶段 | 结果/决策 |
|---|---|
| 官方固件刷写链路 | 用户验证写入和正常运行，保留完整备份 |
| 自定义“乐乐” | 初用 mn6 内存不足，改 mn7_cn；用户确认唤醒和回答 |
| 音乐移植 | 在现有已验证固件移植参考项目 SD MP3 部分，不整体替换板级固件 |
| 缓存设计 | 用户要求复用上次结果，加入 SD 双槽缓存 + RAM 搜索 + 空闲单次刷新 |
| 扫描路径 | 原限定 music 目录得到 0 首，按用户要求改整卡，仅索引 MP3；获得 128 首 |
| 中文路径 | FAT API 改 UTF-8 + heap LFN |
| 点歌立即待机 | 串口确认播放器任务创建失败，32 KiB 栈改用 PSRAM |
| 后续解码失败 | 文件已打开但返回 false，加入阶段/错误码/内存日志；具体原因未复现 |
| 独立调试入口 | 用户要求跳过唤醒/模型；新增独立 debug 变体的 USB 命令与 BOOT 长按 |
| USB 输入适配 | 副控制台需要显式 VFS 注册与 RX 驱动；修复后状态/播放/停止真实通过 |
| 直接播放出声 | 2026-11-19，三首解码通过，用户确认听到音乐 |
| 项目整理 | 独立目录、GitHub 仓库、当前交接文档、通用本地工具；私有数据留本地 |

过时的“必须 music 目录”“曲库 0 首”“仅编译未烧录”不再是当前状态。后续以 HANDOFF 和 VALIDATION 为准。
