## 交互

轻点屏幕中央的助手/表情区域，不需要先说“乐乐”。当前 320×240 屏幕使用
中央 192×120 的透明触摸区域（约 x=64..255、y=60..179），不增加可见按钮。

| 当前状态 | 轻点效果 |
|---|---|
| 待机 idle | 复用功能键入口建立语音通道并开始监听 |
| 回答 speaking | 中止当前播报；下一步由现有语音协议决定，不保证结束整个会话 |
| 监听 listening | 关闭语音通道，结束当前交互 |
| 音乐/通知 notifying | 复用功能键先停止通知/音乐，再尝试语音交互 |
| 启动、配网、连接、激活、升级、测试或错误 | 忽略助手触摸，不触发配网或音频测试 |

菜单打开、传输准备与文件传输模式不执行助手点击；菜单按钮继续执行各自操作。
屏幕始终采用点击交互；即使物理键启用 press-to-talk，也不需要按住屏幕说话。
物理键的按住说话、长按菜单和语音唤醒沿用现有入口。

## 手势与实现

仅接受按下到松开为 20..499ms、每轴最大位移不超过 12 像素的接触。
中途移动超限后即使回到原点也拒绝。有效点击间隔至少 350ms；丢失触摸、
菜单打开/关闭会取消未结束手势。滑动、长按不等价于助手点击。

实现只在板级 CONFIG_LICHUANG_USB_STORAGE 的两个音乐变体启用：
- assistant_tap.h 是有界手势策略；无动态分配，与 LVGL/语音独立。
- LeleMenu::Start 在普通助手启动中安装透明区域，位于菜单顶层之下。
  独立传输分支不调用 Start，不安装该区域，也不构造 Application 音频。
- LVGL 回调仅更新手势状态和一个原子待处理位，不访问 Application。
  既有 100ms 轮询在主任务检查菜单与设备状态，再调用 ToggleChatState。
- 动画和字幕照常绘制。后续歌曲列表需使用单独交互层遮挡该区域，
  不能把歌曲列表点击或滑动继续透传为助手点击。
