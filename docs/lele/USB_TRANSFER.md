状态：2026-11-19，设备运行 f98385c（包含菜单/MSC 和恢复修复），用户确认 SD 功能验证无问题。
最新源码修复传输模式跨重启残留及推出后误拒绝返回；修复版已随显示设置刷入并包含在当前版本，基础功能按用户反馈验收；未逐项记录的专项不推断完成。
不要把下述操作说明当作实机验收结果。本次已获用户当次授权并完成备份烧录；后续再次刷写仍需当次授权。

## 使用流程

正常启动后长按功能键（BOOT）约 **2 秒**，打开菜单；再次长按或短按可关闭。
菜单为英文，与目前 en-US 界面及内置字体一致：

1. 点 **USB File Transfer**。对话进行中会提示先结束对话再试；播放音乐时可以
   自动停止。设备等待播放文件和索引 worker 完成关闭，最长等 30 秒。
2. 保存启动模式、卸载 SD 并重启进入传输模式。正常助手启动时即使插着 USB
   也不会自动共享 SD 卡。菜单 **Back** 仅关闭菜单；新增 Display 页面可调配色与亮度（已刷入，待验收），见 DISPLAY.md。
3. 在 Finder 侧边栏找到 SD 卡卷，可浏览目录和歌曲、复制 MP3、中文改名。
   卷名沿用 SD 原有 FAT 标签，不是一定叫“Lele SD Transfer”；后者是 USB 产品名。
   不格式化卡，不导出内部 Flash/NVS。
4. 在 Finder **推出** SD 卡卷；设备显示可以返回后，点 **Return to Assistant**，
   或短按功能键。不要用拔 USB 线替代正常推出（USB 同时供电）。
5. 设备关闭 USB/SD、保存返回模式并重启回助手，跳过旧缓存，立即安排新索引；
   不等 10 秒空闲、不先用旧目录点播。完成后更新 RAM 及 SD 双槽缓存。

在电脑首次配置 USB 设备之前可以取消；电脑曾经连接后，同一次启动内普通断线/
USB 总线 reset 不视为安全推出。最新源码将传输请求改成一次性：按板上 RESET
或重新上电默认回助手并重新扫描；仅拔数据线、设备仍有其他供电时不会自动退出。
复位不能替代主机刷新写入，仍应先推出，以免丢失尚未落盘的数据。
不要在上电/RESET 时按住 BOOT，除非有意进入 ROM 下载。
板上另一个按键是 RESET；它不是通过应用处理的菜单键。

## 与现有交互的关系

- 两个音乐变体启用 `CONFIG_LICHUANG_USB_STORAGE`；非音乐变体不受影响。
- 该开关优先于 debug 的长按播放首曲。原生 USB 的 music-test status/play/stop
  在正常 debug 模式继续有效；传输模式不启动此任务，也不提供 CDC 串口。
- 菜单打开时，功能键短按关闭菜单，不触发助手；菜单/传输模式屏蔽双击 AEC 切换。
- PTT 模式仍在按下时开始监听；持续到 2 秒阈值后停止监听、打开菜单，松手
  不再触发另一轮助手交互。因此长于 2 秒的 PTT 持续说话与菜单手势不再共用。
- 显示设置已实现且基本交互通过；助手全屏点击已刷入 f98385c，三项基本交互通过（TOUCH.md），Songs 歌曲列表已刷入五首版 a09b405、待布局复验（SONG_LIST.md）。

## 实现与错误路径

`lele_menu.*`：LVGL 顶层模态菜单，触屏回调仅记录动作。ESP timer 限制为最多
一个待处理主线程轮询，避免队列堆积。功能键异步开关菜单通过 Application::Schedule。

`music_storage.h` / `music_tools.cc`：阻止新扫描和点播；正在等待空闲的扫描可完成
一次刷新，关闭/校验缓存后才报告 quiet。`Application::SetMusicStorageBlocked`
取消排队并停止 NotifyPlayer，等待 IsBusy=false（worker 文件已 fclose），不以
“已发 stop”或“屏幕待机”代替文件关闭。超时/NVS 保存失败保留挂载并恢复门禁。

卸载 API 的错误可能发生在 SDK 已释放 card 之后。因此调用前清除全局 card，
卸载失败不回到普通文件 I/O，不重新使用旧指针；保留传输模式和门禁，提示再次
选择传输以重启恢复。不得在错误路径尝试格式化或自动擦除 Flash。

`usb_transfer.*`：NVS namespace `lele_usb`、key `mode` 为 Assistant=0 / Refresh=2 /
一次性 Transfer=3。开始导出 USB 前先将请求持久化为 Refresh；保存失败不导出。
旧版永久传输值 1、未知值或读取失败均回助手并安排刷新，避免继续困在传输模式。
Transfer 启动在摄像头、音乐工具、Application 音频初始化之前分流，SDMMC
1-bit 使用原有 CLK47/CMD48/D0=21。TinyUSB 仅导出 SD，两个禁止格式化选项明确设置。

依赖锁定 `esp_tinyusb 2.4.0`、`tinyusb 0.21.0~6`。2.4.0 的 auto_mount_off 连 SCSI
eject 的处理也会关闭，所以保持默认自动交接；该启动分支没有助手线程访问卡。
APP 挂载完成且没有存储错误时才确认推出；USB 随后取消 configured 仍可返回。
仅断线、没有完成 APP 所有权交接，不能通过同一次启动内的 Return 检查。
先停止 USB task，再删除 LUN（组件拒绝有延迟写入的删除）并关闭 SD，全部成功
才将模式改为 Refresh 并重启。该组件的延迟写错误主要记日志，不能仅凭 Finder
复制窗口结束证明文件完整；验收需读回哈希并留意 UART 日志。

语音模型和摄像头不在传输模式运行；SD 所有权通过重启隔离，不是同时挂载两个
文件系统。退出失败留在当前传输界面，不在本次启动内强行夺盘；可复位回助手。
损坏 FAT/挂载事件失败及异常断电尚需测试卡验证；不能宣传所有异常均已处理完毕。

## 日志与恢复

正常模式原生 USB Serial/JTAG 保持。进入传输模式后 stdout/stderr 改为 UART0，
不向已经让给 OTG 的 PHY 写串口日志。立创设计有 CH334F Hub + CH340K/UART0，
但本机尚未枚举 CH340 串口，驱动和实机日志路径待验收；不擅自安装系统驱动。

最新源码普通 RESET 即回助手；旧版已残留的永久传输标记会在升级后迁移为刷新。
若应用启动失败，恢复路径是按住 BOOT、按一下 RESET、再松开 BOOT 进入 ROM 下载，重新发现
原生串口，再按项目备份/烧录流程操作。该路径需实测；任何重新刷写仍须当次授权。
重新刷应用通常保留 NVS；重刷旧固件仍可能保留永久传输状态，最新源码有迁移处理。
不可为清一个 mode 直接 erase-flash。
