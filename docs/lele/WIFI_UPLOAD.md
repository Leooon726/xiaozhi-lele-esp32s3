# Wi-Fi SD 文件管理（F-009）

2026-11-20：源码已实现，实机未测，尚未提交或发布新固件。现有
test-039cf7b50d51-01 只包含横竖屏功能，不包含网络文件管理。

## 使用方式

设备连接 Wi-Fi 后，电脑/手机在能互相访问的同一局域网内使用，无需云端
账号或公网中继；设备是否能访问互联网不影响局域网文件管理。

1. 长按功能键约 2 秒 → **Wi-Fi File Transfer**。未连接 Wi-Fi 时提示先连接；
   正在对话时先结束会话。设备停止音乐，等待播放文件和索引扫描关闭，最长
   准备 30 秒。SD 未就绪或不能保存重扫标记时不启动可写服务，不格式化卡。
2. 屏幕显示 http://设备IP:8080、8 位十六进制 Code 和 Changes 次数。
   用浏览器打开地址，输入 Code，点 Connect / Refresh。
   这是局域网 HTTP，不提供 HTTPS 或公网转发。
3. 网页从 SD 根目录开始，可浏览普通子目录、返回上层、分页查看，每页最多
   32 项。可新建文件夹、上传文件、重命名、移动文件/目录，以及删除文件或
   **空文件夹**。移动目标填写相对 SD 根目录的完整路径，父目录必须已存在。
   不提供文件内容在线编辑、下载接口或递归删除目录。
4. 上传保存到网页当前目录，支持合法 UTF-8 中文名。同名文件先询问是否覆盖；
   取消不会发送文件内容。删除也需确认；重命名/移动不能覆盖已有目标。
   操作前重新读取元数据和会话版本；若另一个网页修改过文件则返回冲突，
   刷新后重新确认，绝不自动重试破坏性操作。
5. 单文件 1 byte–64 MiB；单个名称最多 180 UTF-8 字节，相对路径最多 232 字节。
   不允许绝对路径、路径穿越、隐藏名称、FAT 非法字符、Windows 保留设备名、
   System Volume Information、$RECYCLE.BIN，以及含 ~ 的名称（防止通过 FAT
   短文件名别名访问受保护文件）。因此部分现有文件不会显示；可用 USB 管理。
   根目录本身、隐藏曲库缓存、上传临时文件和恢复文件不能通过网页修改。
6. 上传成功显示字节数和接收流 SHA-256。多文件依次提交，前面成功的文件
   不因后续失败撤销。Changes 计成功提交的文件或目录变更；响应丢失也可能
   已提交，应刷新检查，避免盲目重传或重复删除。
7. 点设备 **End Wi-Fi Transfer**，或短按/再次长按功能键结束。等待 HTTP
   线程退出、全部文件关闭后才恢复索引和点播，并重建整卡曲库。新索引发布前
   旧索引不可点播；MP3 扫描后出现在 Songs，其他文件保留但不进入曲库。
   原音乐不会自动续播。

会话最多 10 分钟，单文件最多约 2 分钟，单次接收/发送等待 5 秒；慢网络的
大文件可能超时。Wi-Fi 断开、会话到期、累计 8 次错误 Code 或用户结束都会
关闭服务。新会话重新生成 Code，不写入 Git、NVS、串口日志或网页源码。
访客 Wi-Fi 客户端隔离、不同网段或 IP 变化可能导致打不开网页。

管理期间暂停音乐文件访问和索引，不卸载语音服务，不承诺对话时延。
Settings/Songs 页面结束后恢复。USB 使用独立重启模式，不与网络共享 SD。
RESET/掉电后不会自动开放网络服务；NVS 仅保存“曲库需要重扫”标记。

## 文件覆盖与异常恢复

先排他创建隐藏 .lele-upload-随机值.part，使用 2 KiB 缓冲完整接收，再完成
flush/fsync/close。默认拒绝同名；只有明确确认并匹配当前会话版本才覆盖。
覆盖时将原文件改名为同目录 .lele-old-随机值-原文件名，提交新文件后才删除
旧副本。提交失败尝试恢复原名；恢复失败则保留旧副本并关闭会话，提示用
USB/读卡器恢复。如果只是旧副本清理失败，新文件已成功，网页提示保留副本。
中断或失败仅清理本次临时文件，未知恢复文件不会自动删除。

FAT 上多次 rename 并非断电原子事务。覆盖中掉电可能留下 .part、旧副本，
或暂时缺少原名；可用 USB/读卡器检查并恢复。不要在唯一副本上做断电测试。
开启服务前先持久化 dirty 标记，重启时跳过旧缓存并重扫；只有新缓存成功
保存并校验后清除标记，避免改名/删除后仍加载旧路径。真实 SD 掉电和落盘
行为仍须专用测试卡验收。

## Mac Agent / 命令行

所有数据接口需要 X-Lele-Key；查询参数 UTF-8 URL 编码一次。body 为原始文件
数据，不是 multipart/form-data。以下值都是示例，替换为实际设备信息。

~~~bash
# 根目录列表；path 为空表示根目录
curl --fail -H 'X-Lele-Key: ABCD1234' \
  'http://192.168.1.23:8080/files?path='
# 上传到已存在的 music 目录；默认不能覆盖
curl --fail -H 'X-Lele-Key: ABCD1234' \
  --data-binary '@/path/song.mp3' \
  'http://192.168.1.23:8080/upload?path=music%2Fsong.mp3'
shasum -a 256 /path/song.mp3
~~~

上传成功 JSON 包含 saved、bytes、sha256、backup_kept。摘要是接收流校验，
不等于 SD 文件再次读回摘要；端到端验收仍需经 USB/读卡器读回比对。
旧接口 upload?name=song.mp3 保留兼容，保存至 uploads，默认不覆盖。

| 接口 | 参数及结果 |
|---|---|
| GET / | 本地文件管理网页，不包含 Code |
| GET /files | path、offset；返回 path、revision、next、limited、entries（name、directory、bytes） |
| GET /stat | path；返回 directory、bytes、revision |
| POST /manage | op=mkdir&path=目标；op=move&path=来源&to=目标；op=delete&path=目标；无请求 body |
| POST /upload | path=目标，replace=1 才请求覆盖；body 为文件数据 |

删除、移动/重命名和覆盖必须提供 X-Lele-Confirm: yes、X-Lele-Revision（操作前
stat 返回的 revision）。每次成功变更递增会话 revision；不匹配返回 409。
分页 offset>0 同样需要对应列表的 revision，防止跨变更拼接目录快照。
API 不能替代客户端真实确认；命令行 Agent 也应先展示路径/覆盖对象再按用户
授权操作。常见错误：400 参数非法、403 Code 错误、404 不存在、409 冲突或
目录非空、500 SD I/O/恢复失败。目录单请求最多检查 512 项、累计游标最多
16384；limited=true 时明确表示列表未完整显示，改用 USB。

## 实现与验证

- wifi_upload.*：仅显式菜单会话内开启 HTTP server，绑定 STA 接口，单线程
  SD 操作；HTTP handler 不调用 LVGL/应用状态。停止任务负责阻塞式 httpd_stop，
  创建/停止失败保持门禁并重试。
- sd_file_manager.h：路径保护、分页、目录和文件变更；wifi_upload_file.h：
  接收事务和覆盖恢复；wifi_file_page.h：网页交互与确认。
- music_storage.h / music_tools.cc：播放/扫描独占门禁、持久化 dirty 标记和
  结束后的强制重扫；lele_menu.*：主任务推进准备/运行/关闭。
- 限定两个音乐变体的 CONFIG_LICHUANG_USB_STORAGE，仅其引入 esp_http_server。
  主菜单 Display/Songs 共用一行，会话页兼容横屏 320×240、竖屏 240×320。
- 主机回归执行真实文件事务、生产 HTTP 处理函数和菜单协调；包括分页、
  路径/隐藏/别名保护、覆盖取消、fsync/rename/回滚故障、原副本保留、NVS
  标记失败、过期版本拒绝、错误 Code、超时、停止失败重试。网络、RTOS、PSA、
  NVS 使用替身，文件系统为主机临时目录，不代表真实 FAT 或无线验收。
- Node 执行生产网页 JavaScript，验证浏览、上传确认、重命名/移动/删除确认、
  新建文件夹，以及版本冲突后不盲目重试。
- 完整主机套件：Ran 225 tests，OK (skipped=5)。跳过 cJSON/mbedTLS 两组、
  numpy/Pillow/packaging 两项、OpenSSL 开发库一项，不计为通过。两方向真实
  LVGL 回归通过；普通音乐、stock 无音乐、WeChat、Emote 下四个翻译单元共
  16 项语法检查通过，不代表四种完整固件链接或实机通过。
- ESP-IDF v6.1.1 debug 固件构建/链接/打包通过，应用 3,003,200 bytes，槽余
  27%；五分区地址/NVS 范围、容量及合并 ZIP 内容对应检查通过。canonical
  ZIP 仍只含合并镜像，不是可直接交付的五文件安全烧录包。详见 TESTING.md。
- 本轮未打开设备串口、烧录、写真实 SD 或创建新 Pre-release。
