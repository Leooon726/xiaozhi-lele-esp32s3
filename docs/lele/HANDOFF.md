## 目标和已完成工作

设备是立创·实战派 ESP32-S3，16 MiB Flash、8 MiB PSRAM，ES8311 输出 / ES7210 输入。先验证官方固件刷写链路，再在官方 v2.6.0 基线上加入乐乐唤醒，随后移植 SD MP3 播放。没有整体换成参考项目固件。

- 唤醒：MultiNet7 中文模型，命令 `le le`，显示“乐乐”，阈值 0.2，UI 保持 en-US；用户已验证唤醒和对话。
- 音乐：FAT32，扫描整个 `/sdcard`，MP3 扩展名大小写不敏感，根目录/嵌套目录均可，不要求 music 文件夹。
- 索引（已刷入，实机索引 340 首）：1024 首、路径总量 256 KiB、最多访问 16384 个目录项；目录队列仍为 128 项/16 KiB，单路径最多 240 字节。达到任一预算标记 truncated，不能称为全卡全部收录。路径记录集中放 PSRAM，分配失败保留旧曲库。
- 缓存：SD 根目录双槽 `.lele-music-index-a.bin` / `-b.bin`，格式 LLMIDX02。启动读最新有效槽到内存，随后只安排一次后台更新。
- 自动更新：连续空闲 10 秒才扫描；语音/音乐活动使其等待，检查点合作式暂停；每 8 个检查点让出 20 ms。显式重建可跳过空闲等待；已有索引继续可用。
- 播放：复用 `Application::RequestMusic` → `NotifyPlayer` → `DecodeMusic` → `AudioService`。混为单声道、重采样至 24 kHz；数据和任务栈优先使用 PSRAM。
- 工具：`self.music.tf_search`、`tf_play`、`stop`、`status`、`tf_refresh`。
- 调试：独立 debug 变体开放本地 USB status/play/stop，跳过唤醒与云端；BOOT 长按也接入同一路径。无网络调试服务、无任意文件路径/执行代码入口。

## 1024 首扩容状态

用户要求先提高容量，选 1024 首作为保守工程目标，而不是已实测的硬件极限。
`MusicPaths` 用 244-byte 固定记录、几何增长的连续 PSRAM 缓冲；满容量一份
244 KiB，刷新时旧/新/回读验证三份共存最多 732 KiB 路径表（不含目录队列、
音频等其他开销）。无内部 SRAM 回退、无每首 std::string 堆分配；内存不足
不会提交部分扫描或覆盖旧缓存。搜索返回仍最多 20 首/约 6 KB，保持有限响应。
LLMIDX02 格式不变，旧 128 首缓存可以立即加载，随后空闲刷新可补到新上限。
USB/主机脚本编号同步为 0..1023，固件实际曲库大小仍约束可播放编号。

## 不再重复踩的坑

1. MultiNet6 与当前 AFE/显示组合曾内存分配失败；当前用 MultiNet7。
2. FAT API 默认 OEM437 不适合中文路径；变体要求 `CONFIG_FATFS_LFN_HEAP=y`、`CONFIG_FATFS_API_ENCODING_UTF_8=y`。
3. `/music` 限定扫描曾得到 0 首；已改整卡，旧 LLMIDX01 缓存拒绝并重建。
4. 32 KiB 内部 SRAM 播放任务栈在语音后创建失败。当前 MP3 用 `xTaskCreateWithCaps(...MALLOC_CAP_SPIRAM...)`，必须匹配 `vTaskDeleteWithCaps`。HTTP/Ogg 保留 6 KiB 内部栈。
5. USB 是副控制台。只收到日志不代表能读命令：必须注册 USB VFS，并初始化接收驱动。当前 RX/TX 缓冲 256/1024 字节。
6. 主机状态探测必须限速；不要无限写命令或在接收端未就绪时阻塞于 `tcdrain`。现有脚本有写超时、就绪探测和日志。
7. 串口打开可能复位设备；不要把启动重置当成固件崩溃，也不要同时启动多个监视器。
8. 排队成功不是出声；必须分别确认任务创建、文件打开、PCM、队列、物理声音。

## 下一步建议

先用现有 USB 入口稳定复现问题；保留每次选曲编号、状态和解码 stage/error。若语音点歌仍失败，对照云端返回的真实 path 和本地选曲，避免把不同文件混作同一测试。不要先改唤醒或重写云端协议。

后续可做：缩短/消除启动 underrun、完善选曲失败反馈、测试唤醒打断和 BOOT、扩大索引（先核算内存）、暂停/续播/上下首；其他格式由软件解码集成决定，不是 ESP32-S3 只能播 MP3。

OTA 独立推进，见 [OTA.md](OTA.md)。原版自动 OTA 仍保持禁用；不要在自定义音乐变体中无意恢复覆盖。
